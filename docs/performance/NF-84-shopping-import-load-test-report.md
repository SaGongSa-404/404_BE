# NF-84 쇼핑 링크 비동기 워커 1·2·3 부하 테스트 보고서

- 상태: 1차 측정 완료
- 측정일: 2026-07-14
- 기능 PR: #191
- 테스트 이슈: #190
- 후속 실험 브랜치: `local/NF-87-worker2-test`
- 정확성 후속안: [쇼핑 링크 가져오기 정확성 보장 방안](../SHOPPING_IMPORT_ACCURACY_POLICY.md)

## 결론

- 정적 HTML 수집 경로에서 워커 3은 수락된 100건을 모두 60초 안에 완료했다.
- 워커 1은 42건, 워커 2는 73건만 제한 시간 안에 완료했다. 워커 3은 처리 완료율을 각각 58%p, 27%p 높였다.
- 워커 3의 JVM 최대 CPU와 RSS는 워커 1·2보다 증가하지 않았다.
- 그러나 원본 상품값을 대조한 엄격한 검증에서는 워커 3의 100건 모두 하나 이상의 필드가 불일치했다. 처리량 개선이 기능 정확성 개선을 의미하지 않는다.
- 세 실행 모두 Chromium 사용량이 0이었다. 따라서 Playwright가 필요한 최악 조건까지 워커 3의 안전성이 검증된 것은 아니다.
- 워커 3을 운영 기본값으로 확정하지 않는다. 정확성 보완과 Playwright 경로 부하 테스트 후 재판단한다.

## 테스트 조건

- QA 백엔드 한 인스턴스
- 동일 reviewer 계정 하나와 사용자별 활성 작업 상한 101
- 승인 상품 URL: 무신사, 당근, 번개장터
- 총 요청: 101건
- queue 수락: 100건
- 포화 제어 확인: 1건 `429 Too Many Requests`
- 작업 완료 대기 제한: 60초
- 서버 지표: 동일 JVM PID의 CPU/RSS와 Chromium CPU/RSS

이 실험은 크롤링 worker 수에 따른 queue 처리량을 비교한다. 서로 다른 실제 사용자 100명의 인증·데이터 분포를 재현한 실험은 아니다.

## 엄격한 기능 정확성 결과

워커 3 재실행에서는 완료 여부와 별개로 반환된 제목·가격·이미지를 원본 상품의 기대값과 정확히 비교했다.

| 검증 항목 | 불일치 건수 |
| --- | ---: |
| 하나 이상의 필드 불일치 | 100 / 100 |
| 제목 | 100 / 100 |
| 이미지 | 33 / 100 |
| 가격 | 33 / 100 |

대표적인 원인은 다음과 같다.

- 무신사: 상품명 뒤에 사이트 제목과 설명이 붙은 Open Graph 제목을 반환했다.
- 당근: 상품 대표 이미지 대신 공유 카드용 `1200x630` cover 이미지를 반환했다.
- 번개장터 글로벌: 제목에 사이트명이 붙었고, USD 소수 가격을 현재 `Integer`·KRW 중심 모델이 표현하지 못했다.

워크플로 실패는 의도한 엄격 검증이 필드 불일치를 검출한 결과다. 서버 장애나 queue 실패가 아니다.

## 해석과 한계

### 확인된 것

- 정적 HTML 경로에서는 worker를 3개로 늘리면 수락된 100건을 60초 안에 처리할 수 있었다.
- queue backpressure가 101번째 요청을 `429`로 거절했다.
- 이번 조건에서 worker 증가로 JVM CPU/RSS 피크가 악화됐다는 증거는 없다.

### 아직 확인되지 않은 것

- Playwright 렌더링이 필요한 요청 100건의 처리량과 자원 사용량
- 실제 사용자 100명의 인증, DB row, 서로 다른 URL 분포
- 사이트 차단, 지연, redirect, 품절, 옵션·할인가가 섞인 최악 조건
- 제목·가격·통화·이미지가 정확한 검증 성공률

## 다음 검증 순서

1. 성공 응답을 엄격하게 정의하고 도메인별 추출기를 보완한다.
2. 승인 도메인의 고정 fixture와 live canary에서 제목·가격·통화·이미지를 검증한다.
3. 정적 수집 실패 또는 메타데이터 충돌 시 Playwright 경로로 넘어가도록 한다.
4. Playwright가 실제로 실행되는 URL 세트로 worker 1·2·3을 다시 측정한다.
5. 정확성과 최악 조건 자원 사용량을 모두 만족할 때 worker 기본값을 결정한다.

## ADR 판단 상태

- ADR-001 상태: `Accepted` 유지
- 비동기 queue와 backpressure의 필요성: 유지
- worker 3 운영 기본값: 보류
- 재검토 조건: 정확성 보완 후 Playwright 포함 부하 테스트 완료
