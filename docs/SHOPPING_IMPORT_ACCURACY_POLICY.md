# 쇼핑 링크 가져오기 정확성 정책

## 적용 범위

한국 서비스의 승인된 국내 상품 상세 URL만 정확성 검증 대상으로 삼는다.

- 무신사: `musinsa.com/products/{상품번호}`
- 당근: `daangn.com/kr/buy-sell/{상품경로}` 또는 `daangn.com/articles/{상품번호}`
- 번개장터: `bunjang.co.kr/products/{상품번호}`
- 지그재그: `zigzag.kr/catalog/products/{상품번호}` 또는 `zigzag.kr/app/catalog/products/{상품번호}`
- 네이버 쇼핑 브랜드스토어: `brand.naver.com/{스토어}/products/{상품번호}`
- 올리브영: `oliveyoung.co.kr/store/goods/getGoodsDetail.do?goodsNo={상품번호}`
- 네이버 스마트스토어: `smartstore.naver.com/{스토어}/products/{상품번호}`
- 크림: `kream.co.kr/products/{상품번호}`
- 29CM: `29cm.co.kr/products/{상품번호}` 또는 `product.29cm.co.kr/catalog/{상품번호}`
- 에이블리: `m.a-bly.com/goods/{상품번호}`
- 가격: 소수 없는 양의 정수 원화(`KRW`)만 지원
- 필수 결과: 상품명, 원화 가격, 대표 상품 이미지

해외 URL, 외화, 소수 가격은 지원 범위에서 제외한다. 승인 도메인에서 통화가 `KRW`가 아니거나 가격을 양의 정수로 확정할 수 없으면 성공시키지 않는다.

110/110 통과는 현재 표본에서 세 필드의 오답이 없다는 증거다. 외부 사이트의 향후 마크업 변경까지 영구적으로 보장한다는 뜻은 아니다. 구조가 바뀌어 필드를 확정할 수 없을 때 추정값을 반환하지 않고 실패시키는 fail-closed 정책으로 오답 저장을 막는다.

### 추가 도메인 검증 진행 상태

| 사이트 | 정확성 통과 | 접근 실패 | 현재 판정 |
| --- | ---: | ---: | --- |
| 네이버 스마트스토어 | 0 | 11/11 HTTP 429 또는 로그인 전환 | 이 실행 환경에서 원본 대조 불가 |

크림은 공식 홈에서 현재 상품 URL 60개를 확보했다. 모바일 브라우저 식별 요청은 빈 HTTP 500을 반환했지만 공개 미리보기용 식별 요청에서는 상품 HTML이 정상 제공되는 것을 확인해 폴백 요청에 적용했다. 서로 다른 상품 10개를 5개씩 두 배치로 실행했으며 상품명·정수 원화 가격·대표 이미지가 모두 일치했다. 별도 로그인, API 키, 프록시는 사용하지 않았다.

29CM은 판매 중인 상품 상세 후보 14개 중 10개를 검증했고, 에이블리는 공개 공유 링크로 확보한 상품 상세 후보 12개 중 10개를 모바일 브라우저 렌더링으로 검증했다. 두 사이트 모두 상품명·정수 원화 가격·대표 이미지가 원본 상품 데이터와 일치했다. 검색·카테고리 페이지는 검증 대상과 성공 응답에서 제외한다.

앱에서 추가로 발견한 공유 링크 회귀 표본 12건도 별도 검증했다. 올리브영 1건, 지그재그 스토어 링크 3건, 29CM 3건, 에이블리 Airbridge 링크 3건, 무신사 1건은 원본 상품명·현재 할인가·대표 이미지와 일치하도록 보강했다. 당근 채용 공고 1건은 상품 상세 URL이 아니므로 `422 Unprocessable Entity`로 거절하는 것이 정상 동작이다. 지그재그 스토어 링크는 공개 상품 경로로, 에이블리 Airbridge 링크는 모바일 상품 경로로 변환하고, 무신사는 `goodsPrice.finalPrice`를 현재 할인가로 사용한다.

네이버 스마트스토어는 공개 상품 후보 11개를 데스크톱·모바일 브라우저로 확인했지만 데스크톱은 네이버 로그인으로 전환되고 모바일은 모두 HTTP 429를 반환했다. 상품 상세 경로 검증과 모바일 fallback은 구현했지만, 로그인 세션 또는 허용된 출구 경로 없이 정확성 통과로 집계하지 않는다.

2026-07-15에는 로컬 기본 출구 외에 Ubuntu 공식 Tor 패키지의 임시 SOCKS 출구와 QA VM의 별도 출구도 확인했다. 두 경로 모두 크림은 HTTP 500, 스마트스토어는 HTTP 429를 반환했다. 공식 홈을 먼저 방문해 익명 세션 쿠키를 받은 다음 상품으로 이동하는 브라우저 흐름도 같은 제한을 해제하지 못해 운영 코드에는 남기지 않았다.

이 과정에서 승인된 스마트스토어 상품 URL이 `nid.naver.com` 로그인 화면으로 이동하면 최종 도메인만 검사하던 기존 로직이 엄격 검증을 건너뛸 수 있음을 확인했다. 이제 최초 URL이 승인 도메인이면 최종 URL도 승인된 상품 상세 URL이어야 하며, 로그인이나 외부 도메인으로 이동하면 `422 Unprocessable Entity`로 실패시킨다.

## 성공 조건

승인 도메인의 상품 상세 URL은 다음 조건을 모두 만족할 때만 성공한다.

- URL이 해당 사이트의 상품 상세 경로다.
- 상품명이 존재한다.
- 가격이 `0`보다 큰 정수다.
- 통화가 `KRW`다.
- 대표 상품 이미지 URL이 존재한다.
- 세 필드가 동일 상품 페이지의 상품 데이터에서 추출된다.

하나라도 만족하지 않으면 HTTP `422 Unprocessable Entity`로 종료한다. 일부 필드만 있는 결과를 성공으로 집계하지 않는다.

## 추출 원칙

상품 데이터의 우선순위는 다음과 같다.

1. 사이트의 동일 상품용 first-party API 또는 상품 상태 JSON
2. `Product` JSON-LD의 `name`, `offers.price`, `offers.priceCurrency`, `image`
3. 상품 전용 메타데이터와 상품 상세 DOM
4. Open Graph/Twitter 공유 메타데이터

`Product`가 아닌 WebSite·Breadcrumb JSON-LD의 이름은 상품명 후보에서 제외한다. 가격 `0`, 음수, 소수, 외화는 유효한 판매가로 취급하지 않는다. 제목 비교에서는 HTML 렌더링과 동일하게 연속 공백만 하나로 정규화한다.

당근은 일부 응답에서 JSON-LD 가격이 일시적으로 `0`일 수 있으므로, 실제 화면에 노출되는 원화 가격 메타데이터를 함께 확인한다. 무신사와 번개장터도 공유 카드 값보다 상품 상태/API 값을 우선한다.

지그재그는 상품 상태의 최대가보다 `product:price:amount`의 현재 표시 가격을 우선한다. JSON-LD 문자열에 포함될 수 있는 CDATA 경계와 HTML entity를 제거해 상품명과 이미지 URL에 마크업 조각이 남지 않도록 한다.

## 테스트 기준

### 고정 회귀 테스트

CI fixture는 다음을 검증한다.

- 상품 JSON-LD가 공유 제목·이미지보다 우선한다.
- WebSite·Breadcrumb 이름을 상품명으로 사용하지 않는다.
- 지그재그의 현재 표시 가격이 내장 상태의 최대가보다 우선하고 CDATA·HTML entity가 제거된다.
- 가격과 통화가 정수 `KRW`일 때만 승인 도메인 결과가 성공한다.
- 필수 필드 누락, 상품 경로가 아닌 URL, 소수 가격, 외화는 성공하지 않는다.
- 비동기 job과 API 응답에도 동일한 필드가 보존된다.

### 실사이트 테스트

live test는 매 실행 시 국내 실상품 후보를 수집해 다음 네 값을 원본 페이지와 대조한다.

- 정규화한 상품명
- 정수 원화 가격
- `KRW` 통화 코드
- 대표 이미지 URL

세 상품 필드 중 하나라도 다르면 해당 URL은 통과 건수에 포함하지 않고 테스트를 실패시킨다. 최소 검증량은 무신사 18건, 당근 17건, 번개장터 15건, 지그재그 10건, 네이버 쇼핑 브랜드스토어 10건, 올리브영 10건, 크림 10건, 29CM 10건, 에이블리 10건으로 총 110건이다. 지그재그는 고정 canary URL을 항상 포함하고 현재 베스트 페이지에서 추가 상품 URL을 수집한다. 네이버 쇼핑·올리브영·에이블리는 일반 HTTP 요청의 오류 셸 또는 접근 제한을 실제 상품 데이터로 오인하지 않도록 브라우저 렌더링 결과를 검증한다.

## 운영 지표

- `verified_success_precision = 정확한 성공 응답 / 전체 성공 응답`
- 목표: `100%`
- `verified_coverage = 성공 응답 / 전체 요청`

정확도와 성공률은 분리한다. 사이트 차단·삭제·구조 변경으로 일부 요청이 실패하더라도 검증되지 않은 상품명·가격·이미지를 성공으로 저장하지 않는 것이 우선이다.

## 남은 보강 항목

- 필드별 출처(`SITE_API`, `EMBEDDED_STATE`, `JSON_LD`, `DOM`, `OPEN_GRAPH`)를 결과 또는 로그에 기록
- 대표 이미지 URL의 실제 이미지 응답 여부와 상품 ID 연관성 추가 검증
- 고정 canary URL의 변경 감지 및 도메인 adapter 알림
- 위 엄격한 정확성 oracle을 포함한 worker 1·2·3 부하 테스트 재측정
