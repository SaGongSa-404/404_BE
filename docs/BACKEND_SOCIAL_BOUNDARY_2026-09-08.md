# 소셜 게시물 책임 경계 후속

기준: `ae91f3f` (PR #261 이후 develop). 사용자 승인 범위는 내부 리팩토링, 로컬 전후 비교, push/PR 및 필요한 배포다.

## 변경

| 책임 | 소유자 |
| --- | --- |
| 기존 호출 계약 | `SocialPostService` (위임만 수행) |
| 생성·수정·삭제 트랜잭션 | `SocialPostCommands` |
| 목록·상세·내 게시물 읽기 트랜잭션 | `SocialPostQueries` |
| 댓글 수·내 투표·익명 이름 batch 조립 | `SocialPostResponseQueries` (호출자 트랜잭션 사용) |
| 게시물 visible 검사 | `SocialPostLookup` (게시물·댓글·투표가 공유) |
| 이미지 URL·중복 잠금 키 계산 | `SocialPostCreationPolicy` |
| 중복 등록 advisory lock 및 30초 중복 조회 | `SocialPostCreationRepository` (`MANDATORY`) |

댓글과 투표는 더 이상 게시물 facade를 호출하지 않는다. 짧은 댓글·투표 서비스의 트랜잭션과 알림 발행은 그대로 유지하며, 단순히 파일 수를 늘리기 위한 추가 분리는 하지 않았다.

## 보존한 동작

- 사용자 확인 → 선택 item 해석 → 이미지 검증 → 잠금 → 중복 확인 → 생성 순서와 같은 트랜잭션 유지. 없는/다른 사용자의 item은 기존처럼 연결하지 않는다.
- 잠금 키는 기존 SHA-256 길이 접두부 인코딩 및 첫 8바이트를 그대로 사용한다. 잠금과 중복 조회 사이에 별도 커밋하지 않는다.
- 조회의 SQL, cursor, size+1, 차단 필터, batch 댓글 수·투표·프로필 조회와 DTO를 보존한다.
- 댓글의 익명 번호는 전체 첫 댓글 순서로 결정한다. 차단 목록에 맞춰 재번호를 부여하지 않는다.
- 투표의 변경 → flush → 게시물 refresh → 알림 → 응답 순서를 보존한다. DB 트리거가 반영한 집계를 같은 트랜잭션에서 읽는다.
- 신고 가능한 게시물과 일반 visible 게시물은 정책이 다르다. `ReportService`의 조건을 공통 조회로 덮어쓰지 않는다.
- API, DB 스키마, 환경변수, 파일 업로드, 알림 payload 및 전송 정책은 변경하지 않는다.

## 검증 방법과 범위

기존 소셜 API·동시 등록·수정/삭제 권한·댓글 수·닉네임·투표 전환·첫 투표 알림 테스트에 다음을 추가했다.

- 무트랜잭션 잠금 호출 거부 및 상위 트랜잭션 롤백 참여.
- 1/20개 게시물에서 로그인 피드 5회, 익명 피드 3회, 내 게시물 5회 준비 문장 제한.
- 이전 커밋의 실제 읽기 메서드와 현재 구현의 응답·다음 cursor 페이지 동일성.
- facade 위임 및 댓글/투표의 공통 조회 의존성 검사, 정책의 DB I/O 금지.

성능 비교는 테스트 전용 `LegacySocialPostReadPath`에 기준 커밋의 읽기 메서드 본문을 보존한다. 기준 bean과 현재 Queries 모두 Spring 읽기 트랜잭션 프록시를 거친다. 현재 facade 자체는 프록시가 아니다. 동일 JVM·DB·풀에서 AB/BA로 번갈아 실행한다. 상품과 연결된 서로 다른 작성자의 게시물 21개, 투표·댓글을 준비하고 첫 20개를 조회한다.

로그인/익명 20개 조회와 기준-기준 대조군 각각 경로당 준비 1000회, 12블록 × 250회 측정. 독립 테스트 JVM에서 반복한다. DB 쿼리 수와 이 로컬 fixture의 지연을 검증하는 것이며 HTTP 동시 부하·쓰기 경합·운영 p95·실제 FCM 전달 보장은 아니다. 원시 CSV는 `docs/performance/SOCIAL_PAIRED_*.csv`에 기록한다.

## 결과 / 배포

독립 테스트 JVM 3회, 총 측정 54,000회와 준비 18,000회. 아래는 각 실행의 블록별 `(현재 p95 - 기준 p95)` 중앙값(ms)이다. 개별 p95 중앙값끼리 뺀 값과는 다른 통계다.

| 실행 | 로그인 20개 | 익명 20개 | 기준-기준 대조군 |
| --- | ---: | ---: | ---: |
| 1 | -0.012437 | +0.009974 | +0.000937 |
| 2 | +0.029596 | +0.001662 | -0.034501 |
| 3 | +0.028849 | +0.029334 | +0.008110 |

기준 p95 블록 중앙값은 로그인 1.769~1.851ms, 익명 1.034~1.089ms였다. 현재/기준 비교의 최대 차이 크기 약 0.030ms는 동일 코드 대조군의 실행별 차이 크기 약 0.035ms보다 작다. 이 로컬 비교에서는 뚜렷한 성능 저하를 확인하지 못했다. 다만 양의 차이가 여러 실행에서 관측되었으며 작은 추가 비용을 배제하거나 통계적 동등성을 증명한 것은 아니다. 사전에 정한 정량 SLO가 없는 프로젝트의 로컬 비교 근거이지, 운영 성능 보증이나 사후 설정한 공식 허용 오차 판정은 아니다.

로컬 `test jacocoTestReport bootJar` 통과: 730개, 실패/오류 0, 건너뜀 13 (기존 9 + 선택 성능 시험 4). 이전보다 일반 검증 9개와 선택 성능 시험 1개가 추가되었다. 컴파일된 타입 297개 / 참조 787개 / 순환 0. 옮긴 20개 메서드 본문은 수신 객체 이름을 제외하고 기준 소스와 동일함을 대조했다. HTML은 내용 참조 및 inline JavaScript 구문 검사를 수행했고 레이아웃/스크립트 동작은 수정하지 않았다.

원격 CI·QA 배포는 PR에서 별도로 확인한다. 재현 명령은 `BACKEND_SOCIAL_BOUNDARY_VERIFY.txt` 참조.

마이그레이션은 없으며 배포 문제가 생기면 기존 QA JAR 백업 방식으로 이전 코드를 복구한다. 전체 소셜 포트 계층 추가나 기존 접근 예외 통합은 이번 범위가 아니다.
